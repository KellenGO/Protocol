# Protocol 产品规格说明（PRODUCT_SPEC）

## 1. 项目名称

**Protocol**

暂定中文名：**自控协议系统**

一句话定位：

> 一款将 CTDP 与 RSIP 方法论软件化的离线优先桌面应用，用于帮助用户把"自控"从模糊意志问题，转化为可触发、可执行、可记录、可回滚、可迭代的协议系统。

### 当前版本状态

Protocol 当前版本为 **v0.3.0**，已合并以下功能模块：

- **CTDP 主链与辅助链**：主链专注任务、辅助链预约启动、失败裁决、判例化完整闭环
- **判例库管理**：判例可查看详情、编辑标题/描述、废止（保留历史记录）
- **RSIP 定式树**：定式节点、父子结构、点亮/熄灭、递归回滚、事件日志、单定式复盘
- **桌面集成**：系统托盘图标、桌面通知、全局聚焦按钮
- **复盘系统**：按主链复盘统计、失败模式调试汇总、判例复盘列表
- **数据管理**：数据库备份/恢复、备份文件检查、历史 JSON 导出、历史与进度重置
- **发布质量**：CHANGELOG、QA 检查清单、发布流程文档、版本号统一

## 2. 产品不是什么

Protocol **不是**：

- 普通番茄钟
- 普通待办清单
- 普通习惯打卡 App
- 以积分、徽章、排行榜为核心的游戏化工具
- 单纯做"记录学习时长"的统计工具

这些功能中有些可能作为辅助元素出现，但它们不是产品核心。

Protocol 的核心不是"提醒用户要努力"，而是：

> 为用户建立一套能够在关键行为节点上产生约束力，并可在长期生活中递归迭代的自控协议。

## 3. 理论来源与产品化目标

Protocol 基于两套方法论：

### 3.1 CTDP：链式时延协议

CTDP 解决的是**单次任务尺度**上的三个问题：

1. 启动困难
2. 中途放弃
3. 规则被"下不为例"逐渐侵蚀

它通过三项机制实现：

- **神圣座位原理**：将某个标志性触发动作与"必须进入专注任务"绑定，借助任务链的累计价值形成约束力。
- **下必为例原理**：每次争议行为都必须被正式判决为"违规导致链断裂"或"永久允许并写入判例"，防止规则在模糊例外中腐蚀。
- **线性时延原理**：通过"预约启动"机制，把"现在开始"的高阻力，改造成"稍后必须开始"的低阻力承诺。

### 3.2 RSIP：递归稳态迭代协议

RSIP 解决的是**长期生活稳态**上的问题：

1. 为什么 CTDP 在有 DDL、有压力、有目标时特别强，但在无压力、状态散乱、生活负稳态中会失灵
2. 如何不依赖"当下意志力"，而是通过一组轻量、局部最优、能互相保护的小定式，逐步改变生活整体稳态
3. 如何允许失败、回滚与重建，把崩塌视为系统调试，而不是单纯失败

RSIP 的核心产品化概念包括：

- **国策 / 定式节点**：一个明确、低阻力、可执行、能改善局部稳态的小规则
- **国策树**：父节点的稳定，为子节点提供可生存的条件；整棵树共同改变用户的宏观稳态
- **节点点亮 / 熄灭**：某定式当前是否处于生效状态
- **回滚**：父节点崩塌时，依赖其存在的子节点同步熄灭
- **国策组**：将多个相关节点打包，允许一定容错，避免小意外造成系统全盘崩塌
- **失败—强化—再挑战**：每次崩塌都用于发现设计缺陷，再调整规则继续迭代

## 4. 产品总体结构

Protocol 当前包含以下模块：

1. **CTDP 执行系统**
   - 管理主链、辅助链与专注任务
   - 管理失败裁决（违规清零 / 判例化）
   - 管理判例库（查看、编辑、废止）

2. **RSIP 稳态系统**
   - 管理定式树
   - 管理节点点亮与熄灭
   - 管理递归回滚与事件日志
   - 管理单定式复盘

3. **复盘系统**
   - 按主链汇总执行指标
   - 按失败类别聚合调试记录
   - 判例库整体浏览与追溯

4. **数据管理系统**
   - 数据库备份与恢复
   - 备份文件内容检查
   - 历史数据 JSON 导出
   - 历史记录与进度重置

5. **桌面集成**
   - 系统托盘图标与菜单
   - 桌面通知（专注任务结束、预约到期等）
   - 全局聚焦按钮（悬浮快捷入口）

## 5. 目标用户

### 5.1 主要目标用户

- 容易拖延、启动困难的人
- 容易被手机、娱乐、即时快感打断的人
- 普通番茄钟、待办清单、习惯打卡效果不佳的人
- 想将自控方法做成系统化流程，而非依赖"鸡血"的人

### 5.2 非目标用户

- 只想要一个极简倒计时器的人
- 只想统计学习时长、不想执行协议的人
- 期待软件自动替代个人判断的人

## 6. 产品设计原则

### 6.1 协议优先，而非数据优先

统计数据服务于协议执行，而不是反过来。

例如：

- "今天学了多少分钟"不是最重要的
- "预约链是否被履约""主链是否延续""判例是否被谨慎使用"才是核心

### 6.2 规则明确，而非模糊鼓励

产品界面应尽量避免：

- "加油！"
- "再坚持一下！"
- "你可以做到！"

这些话不是核心价值。Protocol 应以明确协议、清晰决策、强约束反馈为主。

### 6.3 用户做裁判，软件做执行器

软件不替用户判断"刷两分钟视频算不算违规"。

软件负责：

- 要求用户正式判定
- 保存判定
- 在未来保持判例一致性

### 6.4 允许失败，但不允许模糊

失败可以发生：

- 链条可以断
- 预约可以失败
- 节点可以熄灭

但每次失败都应该留下清晰记录，而不是被吞没在"算了，下次注意"中。

### 6.5 桌面工具气质

界面风格：

- 简洁
- 冷静
- 克制
- 稍带"控制台 / 协议面板"气质
- 不做花哨游戏化

## 7. 当前功能模块详解

### 7.1 CTDP 主链系统

- 创建主链，设置名称、神圣座位触发动作、专注时长、完成条件
- 查看所有主链列表
- 进入链详情，查看当前长度、最佳长度、判例列表
- 启动正式专注任务
- 任务完成后，主链长度 +1
- 任务失败后，用户必须判定：
  - 违规导致链断裂并清零
  - 当前行为允许，写入判例
- 失败调试记录（触发动作太重、完成条件过高、时间太长、环境不适合、规则不清、状态不足、其他）

### 7.2 CTDP 辅助链系统

- 每条主链内置辅助链配置（触发动作、延迟分钟、完成条件）
- 预约启动：设定延迟后进入确认窗口
- 确认窗口内可履约进入正式任务
- 确认窗口到期后进入待裁决状态（非自动失败）
- 辅助链裁决：违约清零（仅辅助链清零，不影响主链）或判例化
- 辅助链拥有独立的当前长度和最佳长度

### 7.3 判例库

- 主链判例与辅助链判例统一管理
- 链详情页展示协议边界（合并展示两类判例，标签区分来源）
- 判例可查看详情、编辑标题/描述
- 判例可废止（保留历史记录，但不再作为活跃协议边界）
- 判例作用域：`main_chain` / `reservation_chain`
- 判例状态：`active` / `retired`

### 7.4 RSIP 定式树

- 创建根定式与子定式
- 树形缩进展示定式依赖关系
- 点亮（激活）/ 熄灭（停用）定式
- 父节点熄灭时，活跃子节点递归回滚
- formula_events 事件日志（created / activated / deactivated / rollback_child_deactivated）
- 单定式复盘面板：生命周期摘要、熄灭备注、回滚影响、事件历史
- 可编辑定式标题和执行说明
- 熄灭时可填写自定义备注

### 7.5 复盘系统

复盘系统集成在 Dashboard 内，通过“主链复盘 / 失败模式 / 判例复盘”三个平级标签进入。

#### 主链复盘
- 按主链汇总执行指标：完成次数、失败清零次数、判例化次数、预约履约/失败统计
- 展示主链当前长度、辅助链当前长度、最佳长度
- 支持按时间周期筛选

#### 失败模式复盘
- 按 debug_category 聚合失败记录
- 展示各类别的发生次数、最近发生时间、关联链名、最近备注
- 帮助用户识别系统性的协议设计问题

#### 判例复盘
- 判例列表带关联链名
- 按作用域（主链/预约链）和状态（活跃/已废止）展示
- 判例来源追溯（关联的 focus session 或 reservation session）

### 7.6 数据管理

- **数据库信息**：查看数据库路径、文件大小、版本号、各表记录数
- **数据库备份**：选择目标路径，将当前数据库完整备份为 SQLite 文件
- **数据库恢复**：只读检查会先在应用的 `.restore` 目录创建一次性不可变预览。确认页显示原始所选路径以及从预览读取的统计；真正恢复只接受当前检查任务登记的预览，不会重新打开原路径。随后必须经过显式确认、恢复前安全快照和恢复后校验。成功后当前连接立即读取恢复数据；失败不得留下部分恢复状态。
- **恢复失败处理**：恢复后校验失败时立即回退到安全快照；若自动回退也失败，应用会明确报告并保留安全快照路径供恢复。
- **备份文件检查**：源文件按同一文件身份只读打开并固定 SQLite 读取快照；复制前再次以错误感知方式拒绝 `-wal`、`-shm`、`-journal`。取消、重新选择和恢复结束都会清理任务预览；异常退出遗留文件由限龄清理兜底，原始所选文件始终不被删除或修改。
- **统计刷新失败**：恢复已经成功但数据库统计刷新失败时，统计区域保留可见的重试操作，不以空白区域误导用户。
- **历史 JSON 导出**：将所有历史数据导出为结构化 JSON 文件
- **历史与进度重置**：清除所有历史记录和链长度进度，保留链定义和判例库

### 7.7 桌面集成

- **系统托盘**：应用最小化到系统托盘，托盘图标显示协议状态
- **桌面通知**：专注任务结束、预约到期等关键节点发送系统通知
- **通知权限管理**：设置页可开启/关闭通知、请求系统权限
- **全局聚焦按钮**：悬浮按钮，提供快捷操作入口
- **通知测试**：设置页可发送测试通知验证配置

### 7.8 Dashboard 与历史记录

- **Dashboard**：统一承载总览、主链复盘、失败模式和判例复盘
- **总览**：展示当前协议状态与最近活动，不重复展示历史复盘统计
- **协议状态指示**：无活动 / 任务进行中 / 待裁决 / 预约倒计时 / 预约确认窗口，并提供返回活跃流程的入口
- **History**：展示 CTDP + 辅助链 + RSIP 的统一协议时间线
- 支持按事件类型和结果筛选

### 7.9 设置

- 默认专注时长
- 默认预约时长
- 辅助链确认窗口时长
- 通知开关与权限管理

## 9. 关键交互流程

### 9.1 主链任务流程

1. 用户进入某条主链
2. 点击"开始正式任务"
3. 软件显示任务进行中
4. 用户在现实中执行专注任务
5. 到达目标时间后，用户选择：
   - 成功完成
   - 中途失败
6. 若成功：
   - 当前链长度 +1
   - 写入成功记录
7. 若失败：
   - 进入判定界面，填写调试信息
   - 二选一：
     - 违规：链清零
     - 判例化：添加判例，不清链

### 9.2 预约启动流程

1. 用户点击"预约启动"
2. 选择目标链
3. 预约倒计时开始
4. 到期时进入确认窗口
5. 用户在确认窗口内可履约进入正式任务
6. 确认窗口到期后进入待裁决状态
7. 用户必须判定：
   - 辅助链违约清零
   - 当前情况写入预约判例

### 9.3 数据库备份流程

1. 进入"数据管理"页面
2. 点击"备份数据库"
3. 系统弹出文件保存对话框
4. 选择目标路径并确认
5. 备份完成，显示备份文件路径

### 9.4 复盘查看流程

1. 进入 Dashboard
2. 切换到主链复盘、失败模式或判例复盘标签
3. 选择时间周期（最近 7 天 / 最近 30 天 / 本月 / 全部）
4. 查看对应内容：
   - 主链复盘：查看各链的执行指标
   - 失败模式：按类别查看失败聚合
   - 判例列表：浏览所有判例及关联信息

## 12. 术语表

- **主链**：正式任务执行链
- **辅助链**：延时启动的预约承诺链
- **链节点**：一次成功履行协议的记录
- **链断裂**：因违规导致当前链长度归零
- **判例**：某次争议行为被正式认定为以后永久允许的规则记录
- **判例化**：将争议行为写入判例库
- **正式任务**：一次触发主链后必须完成的专注任务
- **预约启动**：先承诺稍后启动，再在约定时限内进入正式任务
- **确认窗口**：预约到期后的一段可履约时间窗口
- **待裁决**：确认窗口到期后、用户做出判定前的中间状态
- **神圣座位**：用户自行定义的标志性触发动作
- **国策 / 定式**：RSIP 中一个明确、低阻力、可执行的小规则
- **定式树**：定式之间的父子依赖结构
- **点亮**：定式进入活跃生效状态
- **熄灭**：定式进入停用状态（可填写备注说明原因）
- **递归回滚**：父定式熄灭时，所有活跃子定式同步熄灭
- **调试分类**：失败时用户选择的失败原因类别
- **复盘**：对协议执行历史的系统性回顾与分析

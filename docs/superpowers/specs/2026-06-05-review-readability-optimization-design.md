# Review 可读性优化设计规范

日期：2026-06-05

## 目标

优化 `Review` 数据分析页的信息层级，让用户在进入页面后先理解本周期整体稳定性，再快速定位最需要复盘的链条，最后查看单条链的明细指标。

本次选择方案 A：**总览摘要 + 异常优先**。

## 范围

### 变更

- 在“按主链复盘”视图顶部增加周期摘要区。
- 从现有 `ChainReviewStats[]` 在前端派生总事件数、完成率、失败数、判例数、最高风险链和最佳稳定链。
- 保留当前每条链的环形图，但强化中心数值、图例说明和明细分组。
- 默认按风险优先展示链卡片，让高失败率或失败次数较多的链排在前面。
- 改善空状态和加载状态，使用户明确当前筛选范围内为什么没有数据。
- 保持现有暗色 Corona 设计系统，不引入新的品牌色或大面积视觉风格变化。

### 不变更

- 不改数据库结构。
- 不改 Tauri 后端命令。
- 不改路由结构。
- 不新增外部图表库，继续使用当前已加入的 `recharts`。
- 不改变“失败模式复盘”和“判例复盘”的数据来源，只做轻量可读性整理。

## 信息层级

页面读法应从上到下形成三层：

1. **周期总览**：当前时间范围内总共发生多少复盘事件，整体完成率如何，失败和判例数量是否值得注意。
2. **异常提示**：指出最需要复盘的链和最稳定的链，让用户不用逐张卡片扫描。
3. **链条明细**：每张卡片展示该链的环形分布、主链指标、辅助链指标和长度指标。

## 派生指标

对每条链：

- 主链成功数：`completed_count`
- 主链失败数：`failed_reset_count + failed_precedent_count`
- 辅助链成功数：`reservation_fulfilled_count`
- 辅助链失败数：`reservation_failed_reset_count + reservation_failed_precedent_count`
- 判例数：`failed_precedent_count + reservation_failed_precedent_count`
- 总事件数：四类成功/失败数量之和
- 完成率：`(主链成功数 + 辅助链成功数) / 总事件数`
- 失败率：`(主链失败数 + 辅助链失败数) / 总事件数`
- 风险分：`失败数 * 2 + 判例数`，用于默认排序和提示

跨链总览：

- 总事件数：所有链总事件数之和
- 完成率：所有成功数 / 所有总事件数
- 失败数：所有主链失败数 + 所有辅助链失败数
- 判例数：所有主链判例数 + 所有辅助链判例数
- 最需要复盘：风险分最高且总事件数大于 0 的链
- 最稳定：完成率最高且总事件数大于 0 的链；并列时总事件数更多者优先

当总事件数为 0 时，完成率显示为 `-`，风险提示不显示链名。

## 组件设计

### 顶部摘要区

在时间范围控制下方、链卡列表上方展示一组摘要卡：

- 总事件
- 完成率
- 失败
- 判例

摘要区下方展示一条紧凑洞察条：

- 有风险链时：`优先复盘：{链名}，失败 {n} 次，判例 {m} 条`
- 有稳定链时：`稳定表现：{链名}，完成率 {rate}`
- 无有效数据时：显示当前范围暂无可分析事件

### 链卡片

每张链卡继续使用当前结构，但调整重点：

- 卡片头部展示链名、状态、完成率和风险标签。
- 环形图中心显示总事件数，下面增加“总事件”小标签。
- 环形图旁增加四项图例：主链完成、主链失败、辅助完成、辅助失败。
- 指标分组保留主链、辅助链、长度三组，但每组视觉密度降低，避免数字墙。

### 排序

按以下顺序排列：

1. 风险分高的链在前。
2. 风险分相同，失败率高的链在前。
3. 失败率相同，总事件数多的链在前。
4. 都相同，保持链名升序，保证稳定渲染。

## 状态与错误处理

- 加载中保持现有加载卡片，但文案改为“正在汇总复盘数据...”。
- 当前筛选范围无数据时，说明“当前时间范围内暂无可复盘事件”，并提示切换到“全部”。
- 单条链总事件数为 0 时，不渲染空白环形图，改用静态空环和 `0`。
- 数据请求失败仍沿用 `console.error`，本次不新增错误 UI；后续可单独做错误状态规范。

## 可访问性与响应式

- 摘要卡和链卡的关键数值使用文本呈现，不只依赖颜色。
- 风险标签使用文字 `稳定`、`关注`、`高风险`。
- 小屏下摘要卡变为两列，链卡改为单列堆叠，环形图和图例不挤压指标。
- 所有按钮和链名链接保持键盘 focus 样式。

## 验证方式

- 运行 `npm run typecheck`，确认派生指标类型正确。
- 运行 `npm run lint`，确认 React/TypeScript 规则通过。
- 在 Tauri 或可用的本地页面中检查 `/review`：
  - “按主链复盘”有数据时显示顶部摘要和排序后的链卡。
  - 时间范围切换后摘要和列表同步变化。
  - 空数据范围显示明确空状态。
  - 小屏宽度下摘要区和链卡不重叠、不溢出。

## 自检

- 无占位符或未定需求。
- 所有派生指标只依赖现有 `ChainReviewStats` 字段。
- 范围聚焦在 Review 页可读性，不包含数据库、后端或路由改造。
